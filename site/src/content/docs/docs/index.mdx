Libero is a self-hostable, LLM-agnostic AI teammate that lives in Slack channels as a shared
agent — one session per channel, not per user — with persistent curated memory, admin-governed
tool access, and asynchronous task execution.

The design principle everything else follows from: **the agent is visibly not a user.** It acts
only as itself, under admin-provisioned service credentials, through an allowlisted proxy, with
every action audited. Channel isolation is a hard admin-defined boundary enforced in code, never
model self-restraint.

<Aside type="caution" title="Early — pre-1.0">
The specification is ahead of the implementation on purpose — treat these pages as the design of
record, not a description of running software.

The governed core is shipped: mutual TLS, per-channel identity taken from the client certificate,
team-sheet enforcement on both gates, the vault, credential injection, redaction, the MCP client
and its pool, OAuth for upstreams that want it, daily caps in both calls and dollars, the
append-only audit log, and the approval broker with its Slack card — plus the gateway, the agent
loop, and the per-channel message store. The layers on top of it are shipped too: curated memory
and semantic recall (phase 2), skills and their lifecycle (phase 3), and ambient mode — the
heartbeat, proactive posts behind a rate window, and `schedule_task` (phase 4). So is the
hardening pass over them: the audit log is hash-chained and an operator command walks it, and
the MCP path streams through redaction rather than buffering behind it (phase 5). An end-to-end
suite attacks all of it. `npx @getlibero/cli init` through `docker compose up` stands the stack
up from a clean checkout.

Every phase is shipped, and releases are numbered: `v0.3.0` is current, with the CLI on npm,
both service images on GHCR, and a [changelog](/docs/changelog/) an operator can upgrade by.
Delivery is milestone-gated per release now, and the open milestone is what lands next.

What is not here: a fired scheduled check runs one bounded turn and can look nothing up;
certificate rotation is two commands and a human edit rather than anything automated. Code
execution exists but is off unless an operator starts the runner, and its `[egress]` allowlist
grants HTTP and HTTPS only. Point it at a scratch workspace before a real one. The
[roadmap](/docs/roadmap) says what lands when, and [self-hosting](/docs/self-hosting) says what a
deployment does today.
</Aside>

## The shape of it

Two deployable services plus per-channel state.

The **gateway and agent** connects to Slack over Socket Mode, routes each `(workspace, channel)`
pair to a shared session, and runs a provider-agnostic agent loop. The **tool proxy** holds every
tool credential, enforces each channel's team sheet, brokers human approvals, meters spend, and
writes the audit log.

The security property the whole design hangs on: tool credentials live only in the proxy, and the
agent reaches tools only through it. Compromise of the agent process — prompt injection, a
malicious skill, a misbehaving model — yields no tool credentials and only the tool surface that
channel's team sheet allows, with every call audited. The agent process holds the Slack tokens and
the model provider key, because the gateway and the loop cannot run without them; neither reaches
a tool the proxy guards. The [security model](/docs/security#which-secrets-are-where) has the
full account.

## What an admin actually configures

One TOML file per channel, kept in your own git repo. It declares which MCP servers the channel
may reach, which tools on them exist as far as that channel is concerned, which of those need a
human click, and what the daily budget is. An `[egress]` block says where sandboxed code may
reach, and no block means nowhere.

Nothing in it is a secret — credentials appear as names, resolved only inside the proxy's vault.

There is no web admin UI in v1, and that is a decision rather than an omission: the files in git
*are* the admin surface.

## Why "libero"

In football, the libero is the free player — the one who sweeps up behind the team, covering
whatever gets through. That is the job here: an AI teammate in your Slack channels that handles
the work nobody is on, under rules your admins write.

And like the libero in volleyball — the specialist who plays under explicit restrictions, marked
by a different jersey — this agent is visibly *not* a user: it acts only as itself, only through
an allowlisted tool proxy, with every action audited. Free player, firm rules.
